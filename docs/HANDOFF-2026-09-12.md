## 5. 🔴 The two structural gaps that block whole features

### 5.1 A driver is never paid through the system

The wallet ledger's complete reason set is:

```
paynet_topup · admin_topup · referral_user · referral_driver · bonus_signup ·
bonus_admin · bonus_promo · bonus_expired · ride_discount · reversal · correction
```

**There is no code by which a driver earns.** The only ride-shaped reason is `ride_discount` —
money *spent on* a ride. A seat is settled in cash between two people and nothing records it.

**Consequences:** `DriverDaromad` (the income screen) **has no data source at all** and cannot be
built. `DriverBalans` can be built truthfully but will not show a driver what they earned.
→ **`docs/PLAN-T101-step19.md`**, five decisions awaiting the owner. ⚠️ `api/rides.ts`
(`startRide` / `completeRide` / `cancelRide`) **looks** like the missing backing and is **DEAD** —
the `/rides` router is commented out (`routes/index.ts:149`). **Do not wire it.**

### 5.2 The four order scopes all search identically

Specified 2026-08-30, re-confirmed by the owner 2026-09-12, unbuilt until today.
Search takes a district id, resolves it to a NAME, and runs `from_text ILIKE '%name%'` — so
`Farg'ona` matches the province, the city **and** the district, and adm2/adm3 are the same query.
→ **`docs/PLAN-T102.md`**. Rules done; migrations written, not run.

## 7. Where T-102 stands, and what to do next

**Done:** `src/utils/geoMatch.ts` + `geoMatch.test.ts` — **46 cases, API suite 238 → 284, red on
all 16 mutations**, file restored byte-identical each time.

🟢 **THE WHOLE RULE IS ONE SENTENCE:**

> An offer matches an order when, **for BOTH directions independently**, the order's node at the
> order's match level is **among** the offer's nodes at that level.

Everything follows from it: *"uni ichki qismlari emas"* needs no code (comparing cities never
looks inside a city), `aro` ≡ `viloyat` and `tuman` ≡ `yaqin` as queries, and a more precise offer
matches for free. **The four scopes differ in VALIDATION, not matching.**

⚠️ **One product call, one constant.** `LOOSE_PARENT_MATCH` (currently `true`): a district-only
offer place serves a QFY-level order in that district, and such matches are labelled
`'district'` rather than `'exact'`. Flip the constant to make it strict; nothing else changes.

### T-102c is measured and splits into three (increasing risk)

🟢 **The multi-select UI ALREADY EXISTS** — `selectedFromCities` / `selectedToCities` are arrays
and the sheet fills them. The set model is not new UI.

🔴 **But the ids are thrown away and smuggled through `stops`.** Every district after the first
becomes a fake `DriverOfferStop` carrying only `label_text` (wizard lines 897-915). The edit path
recovers them by splitting `from_text` on commas and testing whether a part
`includes('viloyat')` (lines 343-355). **A district whose name contains that word is mis-parsed,
and a renamed district silently stops loading.** This is a live defect, not just debt.

⚠️ **The wizard stops at `endLevel="district"`; the word "settlement" appears ZERO times.** So a
driver cannot name a QFY at all, and `tuman`/`yaqin` need **genuinely new UI**, not rewiring.

1. **Persist what is already collected** → `driver_offer_places` rows instead of fake stops.
   *Deletes the text round trip and the `includes('viloyat')` guess on its own.*
2. **Stop faking stops** so a real intermediate stop means what it says.
3. **Add QFY selection** (`endLevel="settlement"`, multi) so the deeper scopes can match.

**Remaining after that:** T-102d (send/store the scope) · T-102e (rewrite the search, keep a text
fallback for pre-T-102 rows) · T-102f (admin neighbours screen, ~200 districts) ·
🔴 **T-102g the backfill — the riskiest step; a wrong id is worse than none, NULL is the safe
failure** · T-102h.

## 10. Traps this project keeps hitting — worth reading before the next session

1. **A card's tick outvotes its own body.** Step 7 was titled "`SearchOffersScreen` → `UserQidiruv`"
   and ticked; its body said it swapped colours only. Two other places said the screen had no step.
   **The screen went six weeks unrebuilt.** *When a card and its body disagree, the body wins.*
2. **A negative claim from a grep is worth exactly the path it ran against.** Four of today's nine
   corrections were "X does not exist" statements made from searching the wrong directory —
   including two of mine.
3. **`tsc` cannot see a translation key.** Two namespace errors today would have rendered raw keys
   in all three locales. Only a checker that *evaluates* the translations catches it.
4. **The artboards' `brand` green fails contrast** (2.29-2.56:1) wherever it carries meaning.
   Substituted with `action` **three times** on this card. The palette header says so outright.
5. **A checker that cannot go red proves nothing** — and today one was broken *in the way that
   looks like success*: esbuild inlined a test stub, so the disk layer silently answered every
   assertion and the memory layer was never tested. Three mutations stayed green.
6. **The shell halves backslashes**, even in quoted heredocs. Write scripts with the Write tool.
   Locale files are **CRLF** — a prover whose anchors end in a bare newline matches nothing.
7. **Derive the semantics, then measure the DATA SHAPE separately.** Today's largest error: the
   matching logic was right and the schema was modelled from an assumption.
